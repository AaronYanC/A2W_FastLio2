# A2W Fast-LIO2 工程化仓库设计

## 目标

将当前 ROS 2 工作区整理为可迁移的 `A2W_FastLio2` 项目，并保留两个清晰的
Git 节点：第一个提交备份当前可运行状态，第二个提交完成工程化整理。最终项目在
任意 Ubuntu 22.04 + ROS 2 Humble 主机上均可从仓库根目录安装依赖、编译和运行。

本项目仅管理 PC 端 FAST-LIO2 环境。任何脚本都不得登录、修改或停止 A2-W
机器人上的系统、网络、雷达参数、Hesai 驱动或宇树自带 SLAM 服务。

## 仓库边界

当前工作区目录直接作为仓库根，不创建同名嵌套目录。仓库只追踪源码、配置、
启动文件、脚本、测试和文档。以下内容属于本机构建或运行产物，不进入 Git：

- `build/`、`install/`、`log/`
- `maps/` 中生成的 PCD 地图
- 编辑器、Codex 和 agent 的个人工作目录
- Python 缓存和临时生成配置

现有 home 级 Git 仓库不属于本项目，不得暂存、提交或修改。本项目必须在工作区
根目录建立独立 Git 元数据。

## 上游源码

`src/FAST_LIO_Hesai` 保留为 Git submodule，URL 指向 Hesai 官方仓库，并锁定当前
已验证的 ROS2 分支提交。其 `include/ikd-Tree` 继续使用上游递归 submodule。

初始化脚本负责执行递归 submodule 初始化，因此用户既可以使用
`git clone --recurse-submodules`，也可以普通 clone 后直接运行项目初始化脚本。
项目工程化代码不得修改 Hesai submodule 的工作树。

## 提交结构

### 提交一：当前版本备份

第一次提交保存整理前的项目文件和 Hesai submodule 精确版本，排除生成目录、地图
和个人文件。该历史提交允许包含当时已有的本机路径及测试不一致，以真实记录当前
可运行状态。

### 提交二：可迁移工程化版本

第二次提交加入完整的目录约定、依赖安装、构建、运行、配置生成、测试和中文说明。
最终工作树不得包含项目作者主机的 home 路径或旧项目名称。历史备份提交中保留的
路径不作为最终工作树扫描失败条件。

## ROS 2 bringup 结构

新增独立的 `a2w_fastlio2_bringup` ROS 2 包，负责：

- 复用 Hesai 官方 `fast_lio` 节点，不复制或修改其算法源码。
- 从包 share 目录加载 JT128 参数和 RViz 配置。
- 暴露地图文件路径、是否保存地图、是否启动 RViz 等 launch 参数。
- 通过启动参数覆盖 `map_file_path`，避免 YAML 保存任何仓库绝对路径。

项目根脚本从自身位置解析仓库根，再将输出地图路径作为 launch 参数传入。默认地图
写入仓库根的 `maps/`，用户可以通过环境变量或命令行参数覆盖输出位置。

## CycloneDDS 网络配置

仓库保存不含 PC 固定地址的 CycloneDDS 模板。运行脚本先在 PC 全局 IPv4 接口中
选择与 A2-W Hesai 主机地址同一直连子网的接口，以避开 VPN/TUN 路由；找不到直连
匹配时才使用路由探测结果。脚本取得接口和源 IPv4 后生成仅本次运行使用的 XML。

网络接口、PC 地址和 DDS peer 均支持环境变量覆盖。探测失败时脚本必须给出明确错误
和覆盖方法，不能修改本机永久网络设置，更不能修改机器人配置。

## 工具脚本

项目提供以下稳定入口：

- 初始化/依赖脚本：初始化递归 submodule，并通过 `rosdep` 安装工作区依赖。
- 构建脚本：加载 ROS 2 Humble 环境并执行 `colcon build`。
- 在线运行脚本：生成运行时 DDS 配置并启动 JT128 FAST-LIO2。
- 建图保存脚本：创建地图目录，以启用 PCD 保存的配置启动节点。
- 输入检查脚本：只读检查 `/lidar_points` 与 `/lidar_imu`，不操作机器人服务。

脚本必须可从任意当前目录执行，支持常用环境变量覆盖，并对缺失 ROS、未构建工作区、
缺少命令或网络探测失败提供可操作的错误信息。

## 配置策略

JT128 参数由 bringup 包维护。普通在线配置默认不保存地图；建图保存配置启用
`pcd_save_en`，地图路径由 launch 覆盖。叶素尺寸在配置和测试中使用同一个明确值，
避免旧版本中配置与测试不一致。

ROS 发行版系统路径属于平台约定，但脚本允许通过 `ROS_DISTRO` 或 ROS setup 路径覆盖。
项目自身文件不得引用固定用户名、固定 home 目录或旧工作区路径。

## 测试和验收

自动化检查至少覆盖：

1. 从任意当前目录调用脚本时，仍能解析正确仓库根。
2. DDS 运行时配置能使用探测值或环境变量覆盖值。
3. 普通模式与保存模式选择正确参数，地图路径指向运行时解析结果。
4. 当前追踪文件中不存在固定用户名、home 路径或旧项目名称。
5. Hesai 和 ikd-Tree submodule 均初始化并处于锁定提交。
6. Shell 静态检查、项目单元测试和 `colcon build` 全部通过。
7. 使用临时目录进行一次递归 clone/checkout 验证，证明仓库不依赖原始工作区路径。

最终通过现有 GitHub SSH 身份，经 GitHub SSH 443 端口推送到目标私有仓库。推送前
再次检查提交内容、超大文件、敏感信息、submodule 状态和远端分支，禁止 force push。
